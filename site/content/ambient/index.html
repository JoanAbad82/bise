the same in all four

  • fn is a walkie-talkie. hold, talk, let go: “:* got it.”, then “main is on it.” it is always main, on bise's own backend; the terminal and this app are two views of the same thread.
  • main sees your screen. on fn down, one screenshot of the front window goes with your words, so “this gray” means something. you never see it; the only sign is a blink of pink corners and “main sees Chrome · …”.
  • needs you is a system notification. answer with 1 / 2, a click, or by holding fn.
  • outputs open in your browser, served by bise on localhost, each type with its own note tools: a page (pins), a doc (pen, margin), a PR (line and screenshot comments), an image (draw, pick). one per direction here; the real app would have all of them. “send” gives every note to the agent that made it.
  • spotlight for when you can't talk: type to main, start an agent, open an output.

questions for you

  1. which direction, or which mix (e.g. A's capsule with B's editor)?
  2. the screenshot: when. on every fn press (the mocks), or on every message, typed ones too?
  3. what main never sees: skip password managers, banking, private windows by default? a list you edit?
  4. several screens: the one with the cursor, the one with the front window, or all of them?
  5. the permission: macOS asks for screen recording at first launch. ask at install, or the first time you say “this”?
  6. fn on macOS opens emoji or dictation by default: bise would ask you to set it to “do nothing”. fine, or another key?
  7. always there, or not: is the panel always there (the idle line under the menu bar), or only when something happens?
  8. out loud or not: does main speak its answers by default, or only text unless you talked?
