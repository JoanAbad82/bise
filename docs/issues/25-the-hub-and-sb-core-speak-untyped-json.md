# 25 · the hub and sb-core speak untyped JSON

Status: in progress. Chunk 0 (schema, generator, fixtures) on
`sb/core-schema`; chunks R, B and F after it. Debt D1 + D2 of the
architecture page (v31/v32, the user's pick). Brief: architect's
`brief-core-schema.md`. Label: hub, sb-core, protocol.

## The problem

Measured at main 84ddc10d:

- **Rust → sb-core**: 41 `json!({"t": …})` literals in
  rust/switchboard/src/core.rs (more in core_user.rs, core_wake.rs,
  merge.rs, every.rs, signin_card.rs). sb-core reads each field by name
  with `C.get_s(i, "…")`, and picks the input with `in_tag`
  (bend/hub/core.bend:3726), a 49-step `Bool.pick` chain where
  event-wake hit a merge conflict.
- **sb-core → Rust**: effects are built by hand,
  `J.kv("fx", J.JStr{"deliver"}) <> …` (29 in core.bend, 2 in main.bend),
  and read back in `Hub::effect` (core.rs:2615) with
  `match jstr(f, "fx")` and string-keyed reads. switchboard has 766
  `json!` and 804 string-keyed reads in all.
- **Transcripts (D2)**: 30 kinds of `sb <kind> : …` text lines, 7 of them
  new in the last 3 weeks, parsed back by rust/proto/src/thread/lines.rs
  (1,166 lines), which must read every shape ever written.
- **The cost**: the 29 commits that touched core.bend in 21 days touched
  4.2 of 7 layers and 17.4 files each on average. Every new feature
  copies the pattern by hand, and a name typed differently on each side
  is a silent default ("" or 0), not an error.

## The plan

A kind that crosses the seam (an input, an effect, a feed record) is
declared once, in `bise_proto::core` (rust/proto/src/core/). From the
declaration:

- Rust gets serde types (`In` tag `t`, `Link` tag `t`, `Fx` tag `fx`,
  `Feed` tag `sb`, each with `Unknown`), and a table of every kind and
  field;
- sb-core gets a generated decode of `In`/`Link` into Bend records with a
  binary-search tag lookup, and generated `Fx` encoders in wire order
  (bend/hub/gen/, written by rust/proto/tests/core_gen.rs);
- the fold reads `Feed` records through serde, and every older text shape
  in one place.

What stays hand-written: the decision in sb-core and its law.

Chunks (each owns its files; chunk 0's schema is the others' contract):

- **0 · schema + generator** (new files only): the four enums, the
  generator and its stale check, the Bend laws (decode∘encode is the
  identity, the tag table), the fixtures captured from real traffic
  (tests/core_capture.py, a proxy in sb-core's place on throwaway hubs
  with the fake provider), gate.sh's mapping.
- **R · the Rust side** (core.rs, daemon/ call sites): inputs sent as
  `In`/`Link` (in a `Step`), effects read as `Fx`; an unknown fx logged
  as today.
- **B · the Bend side** (bend/hub/*.bend): `in_tag` and the field reads
  go, the generated decode in; effects built with the generated encoders.
  The records inside sb-core stay. ALL PROOFS CHECK; core.bend only
  shrinks.
- **F · the feed** (rust/proto/src/thread/, the line writers): new lines
  are `sb <kind> :: <json>` of `Feed` (two colons: no old writer ever
  wrote ` :: ` after the kind, so the form is one prefix test, architect
  m_18679); every old shape moves to
  `thread/legacy.rs` behind `upgrade(line) -> Option<Feed>`, with a corpus
  of each shape ever written. Transcripts and the journal are never
  rewritten (positions are ids; a rollback must still read them).

The generated `bend/hub/gen/*.bend` files are exempt from the 1,000-line
rule (bise-implement rule 6) by their header "generated by bise-proto,
never hand-edited" (laws.bend is ~1,400 lines): no one reads or edits them
by hand; the declaration in `bise_proto::core` is what is kept short.

`Feed` is a draft until F's first writer lands: its fields come from
today's text parsers and may still change before anything writes them.
`"v": 1` only on the records whose shape grew before or may change: card,
approval, pr, landed, scheduled, wake.

## Done when

- `rg 'json!\(\{"t"' rust/switchboard/src --glob '!*tests*'` → 0;
- `rg 'jstr\(f, "fx"\)' rust/switchboard` → 0;
- `rg 'String.eq\(t, "' bend/hub --glob '!codec.bend'` → 0 (the input
  and link dispatch), and `in_tag` is gone from core.bend;
- `rg 'J.kv\("fx"' bend/hub --glob '!gen/*'` → 0;
- lines.rs reads no `sb <kind> : ` prefix outside `thread/legacy.rs`; new
  writers write only `Feed` JSON;
- docs/architecture-principles.md has the rule "a new sb-core input,
  effect or feed kind is declared in `bise_proto::core`; its Bend codec
  and Rust type are generated";
- a dry run here: a toy input kind touches the schema, one Bend decision
  and its law, nothing else (its diff stat);
- core.bend and core.rs shorter than at 84ddc10d (4,008 and 3,366 lines).

Each sha keeps: the link traffic of the capture corpus equal as JSON
values, the journal byte-equal on a replay, the e2e transcripts equal
(but the kinds F moves, named), ALL PROOFS CHECK (4 shards),
`old_core_replay` for -28, -29 and main.

## Not in this slice

  codec.bend (and model.rs's serde) is the next slice (architect m_18761).
- the typed hot view from sb-core (D3, issue 21).
